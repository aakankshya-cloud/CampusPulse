Read the limits before the metric

    No clinical validation, calibrated risk probability, or diagnostic interpretation is provided. Student IDs are excluded from model features. Original holdout results and development-only CV results are reported separately.

    The pipeline you can explain

    Define the target

    A synthetic 20–80 score in demo mode. Real training requires a measured outcome and documented timing.

    Keep participants separate

    Reserve 20% of students for final testing. Use five grouped folds inside the remaining data.

    Learn from behavior

    Median imputation, model comparison, and features for sleep, activity, social time, study, screens, and routine.

    Inspect the explanation

    Permutation importance describes the model globally; median replacement explores local sensitivity.

    Retrieve, then optionally generate

    TF-IDF retrieves two authored support cards. Optional Ollama generation uses those cards and a basic output filter.

    Step 1 · Understand the data

    What do the students’ records show?

    Loading exploratory analysis…

    Routine patterns and questionnaire scores

    Each dot represents one development student. Left to right means more of the behavior; higher means a higher questionnaire score. A pattern in these dots does not prove that one causes the other.

    How much data was actually recorded?

    The left plot counts students at different questionnaire scores. The right plot shows how many days had a valid sleep report or a recorded sensor event. Orange lines mark the middle values. A day without an event could mean no event or missing recording.

    Prepared-data checks

    Missing values here are counted after cleaning and coverage filtering. Zero missing values does not mean every day of raw sensor data was recorded.

    FeatureStudents observedMissingSpearman correlation

    Correlation runs from −1 to +1: negative means opposite directions; positive means the same direction. With this small sample, these patterns are exploratory. Activity and actual screen-use plots are not included because those features are not yet measured by this importer.

    Step 2 · Feature engineering

    Turn daily records into useful summaries

    Loading candidate features…

    Feature engineering produced eleven candidate inputs. Model evidence shows which configuration was chosen. Extra features do not automatically make predictions better.

    For example, instead of just knowing a student's average sleep, we can calculate whether they slept less in the second half of the study. Negative change means the recorded value became smaller later.

    Look at the new summaries

    Each dot is one development student with sufficient data. The exercise feature is self-reported. The nighttime phone feature measures recorded locked duration, not actual phone-use time. The training pipeline handles unknown values inside each validation fold; it does not fill them using validation students.
